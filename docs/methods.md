# Methods

This document describes the implementation in enough detail to reproduce and
critique the analysis. The README is the user-facing guide; this file records
the methodological choices and their rationale.

## 1. Data acquisition

### Proteomes

Reviewed (Swiss-Prot) entries were downloaded from the UniProt REST stream
endpoint:

```
https://rest.uniprot.org/uniprotkb/stream
  ?format=fasta
  &query=(organism_id:<taxid>) AND (reviewed:true)
```

- *Escherichia coli* K-12: taxid **83333**
- *Bacillus subtilis* 168: taxid **224308**

The run reported in the README used UniProt release **2026_04** and yielded
4,531 and 4,191 sequences respectively. FASTA headers have the form
`sp|P12345|NAME_ORGANISM Description`, and the pipeline extracts the accession
`P12345` from the middle field. The full description/entry name is retained for
the HTML report.

### GO annotations

Annotations were retrieved from the QuickGO annotation search API:

```
https://www.ebi.ac.uk/QuickGO/services/annotation/search
  ?taxonId=<taxid>
  &geneProductType=protein
  &evidenceCode=ECO:0000269
  &limit=200
  &page=<n>
```

`ECO:0000269` is the ECO term for experimental evidence and returns its
descendants. The script pages through JSON responses (the bulk GAF download is
capped at 10,000 annotations, which truncates the *E. coli* set) and then keeps
only rows whose GO evidence code is one of:

```
EXP  IDA  IPI  IMP  IGI  IEP  HTP  HDA  HMP  HGI  HEP
```

Rows with a `NOT` qualifier (e.g. `NOT|involved_in`) are discarded because they
assert the absence rather than the presence of an association. The result is a
TSV with `accession, go_id, evidence_code, qualifier, aspect, reference,
assigned_by, organism, taxon_id`.

**Why experimental evidence only?** The evaluation asks whether two proteins
share *function*. Electronic annotations such as IEA and ISS are frequently
derived from sequence similarity, domain matches, or orthology. Scoring
sequence-based predictions against them would make the comparison partly
circular: a DIAMOND hit would tend to agree with an annotation that was itself
inferred from a sequence match. Restricting to experimental codes makes the GO
signal at least partly independent of sequence similarity. The high-throughput
experimental codes (HTP/HDA/HMP/HGI/HEP) are included because the GO Consortium
classifies them as experimental, but they can be noisier than low-throughput
experiments; this is a documented source of heterogeneity.

### Ontology

`go-basic.obo` is downloaded from
`https://current.geneontology.org/ontology/go-basic.obo`. The parser keeps the
`is_a` and `relationship: part_of` edges only.

### Test dataset

A small committed dataset is generated by `scripts/download_data.py
--mode test`:

- 200 proteins per organism, sampled without replacement using Python's
  `random.Random(seed=42)` and written in the original FASTA order.
- All experimental annotations for the sampled accessions.
- An OBO slice containing every annotated term and all of its `is_a`/`part_of`
  ancestors, so propagation behaves identically in the test and full runs.
- `testdata/metadata.json` records the seed, sizes, and source counts.

The test dataset is committed; full data is git-ignored.

## 2. Embeddings

Script: `bin/embed.py`.

- Model: `facebook/esm2_t6_8M_UR50D` (320-dimensional hidden states,
  ~8M parameters); configurable with `--model`.
- Sequences longer than 1,022 residues are truncated *before* tokenisation.
  The tokenizer uses `max_length = 1024`, leaving room for the ESM `<cls>` and
  `<eos>` special tokens. The number and accessions of truncated sequences are
  logged and written to `<name>.meta.json`.
- Forward passes run in batches under `torch.no_grad()`, on CPU by default.
- **Mean pooling:** for each sequence, the hidden states of real residues are
  averaged. Padding, `<cls>`, `<eos>`, `<pad>`, and `<mask>` token ids are
  excluded using the token ids and attention mask. This is implemented in
  `mean_pool_masked` and unit-tested with synthetic tensors.
- Embeddings are saved as float32 `(n_proteins, hidden_dim)` arrays in FASTA
  order, with a parallel `.ids.txt` file and a `.meta.json` run record.
- Embeddings are *not* L2-normalised at this stage; normalisation happens in
  `find_pairs.py` so the raw vectors remain reusable.

Mean pooling was chosen because it is simple, deterministic, and cheap on CPU.
It loses residue-level and domain-level information; see Limitations.

## 3. DIAMOND

Script: process `DIAMOND` in `main.nf`.

```bash
diamond makedb --in proteome_b.fasta -d target_db --threads <cpus>
diamond blastp \
  -q proteome_a.fasta -d target_db \
  --very-sensitive \
  -e 1e-3 \
  --max-target-seqs 0 \
  --max-hsps 1 \
  --threads <cpus> \
  --outfmt 6 qseqid sseqid pident evalue bitscore \
  -o diamond_hits.tsv
```

Important details:

- `--max-target-seqs 0` disables DIAMOND's default cap of 25 target sequences
  per query. Without this, group (b) would be an arbitrary top-25 subset.
- `--max-hsps 1` keeps one HSP per target; `find_pairs.py` additionally keeps
  the best HSP per `(query, target)` pair if several are present.
- Query and target ids are UniProt headers of the form
  `sp|P12345|NAME_ORGANISM`. The parser maps both to the bare accession so they
  join correctly with embedding ids and GO annotations.

## 4. Pair finding

Script: `bin/find_pairs.py`.

1. Load embedding matrices A `(n_a, d)` and B `(n_b, d)` and their id files.
2. L2-normalise each row (zero rows remain zero).
3. Compute the full cosine matrix `A_norm @ B_norm.T` in float32.
4. For each A protein, retain the top `k` B proteins using `argpartition` and
   sort each row descending.
5. Parse DIAMOND hits, keep the best HSP per `(a, b)`, and mark
   `sequence_hit=True` for any pair present.
6. **Embedding-only candidates:** top-k pairs with `sequence_hit=False` and
   `cosine >= cosine_threshold` (default 0.9). The threshold removes weak
   neighbours; cosine values from mean-pooled ESM-2 are compressed toward 1, so
   0.8 is too permissive (in the test set it retained ~94% of top-k pairs).
7. **Random control:** sample uniformly from `A × B`, with replacement rejected
   until unique, excluding all top-k pairs and all DIAMOND hits. The sample size
   equals the number of embedding-only candidates. A fixed seed makes it
   reproducible. If the requested size exceeds the available space, the script
   warns and returns as many unique pairs as possible.

Outputs: `pairs.tsv` (all top-k, joined with DIAMOND), `diamond_pairs.tsv`
(all significant DIAMOND pairs), `random_pairs.tsv`, and
`pairs_summary.json`.

Group definitions used downstream:

- (a) `embedding_only` = top-k, no DIAMOND hit, cosine ≥ threshold.
- (b) `diamond_hit` = the complete DIAMOND hit table.
- (c) `random` = random control.

## 5. GO evaluation

Script: `bin/go_eval.py`.

### Term propagation

- Parse the OBO file into `go_id -> {parent go_ids}` using `is_a` and
  `relationship: part_of` edges.
- For each protein, union its annotated terms and all ancestors reachable by
  depth-first traversal. This includes the three roots.
- Terms absent from the OBO are retained as isolated nodes and counted in
  `eval_summary.json`; in the full run none were missing.

### Scoring

Only pairs where **both** proteins have at least one experimental annotation
are scored. The numbers of input and unscorable pairs are reported per group.

- **Jaccard:** `|A ∩ B| / |A ∪ B|`, where `A` and `B` are propagated term sets.
- **Jaccard without roots:** the same after removing `GO:0003674`,
  `GO:0005575`, and `GO:0008150` from both sets. This is a sensitivity analysis,
  because the roots are shared by every annotated protein.
- **Resnik:** information content `IC(t) = -log(freq(t)/N)` is estimated from
  all annotated proteins in the run, where `freq(t)` is the number of proteins
  whose propagated set contains `t`. Pair similarity is the maximum IC among
  common terms (the most informative common ancestor). This is a secondary
  metric; the primary inference uses Jaccard.
- Shared terms in `pairs_scored.tsv` are sorted by decreasing IC, so the most
  specific shared terms appear first in the report.

### Statistics

- Two-sided Mann-Whitney U tests: (a) vs (c) and (b) vs (c).
- Cliff's delta: `2U/(n₁n₂) − 1`, where `U` is the Mann-Whitney statistic for
  the first sample. Positive values mean group (a) (or b) tends to have higher
  Jaccard than random.
- Holm-Bonferroni adjustment across the two comparisons.
- The hypothesis is declared supported when (a) vs (c) has an unadjusted
  two-sided p < 0.05 and Cliff's delta > 0. Both raw and Holm-adjusted p-values
  are written to `eval_summary.json`.

## 6. Report

Script: `bin/make_report.py`.

The report is a single HTML file with embedded CSS and a base64-encoded PNG. It
contains:

- headline verdict with the key statistics;
- violin + box + jitter plot for the three groups;
- summary table with input/scorable counts, means, medians, effect sizes and
  p-values;
- sensitivity note for the root-removed analysis;
- top 20 embedding-only pairs by cosine, with protein accessions, entry names,
  descriptions, cosine, Jaccard and most-specific shared GO terms;
- methods and limitations.

No external JavaScript, fonts, or images are required.

- Pinned environment: `environment.yml` (Python 3.11.18, NumPy 2.4.6, SciPy
  1.17.1, Biopython 1.88, PyTorch 2.15.0+cpu, transformers 5.22.1, goatools
  1.6.9, DIAMOND 2.2.8, OpenJDK 17).
- Nextflow 26.10.5, Java 17.
- Test subsampling and random control both use seed 42.
- Full data are downloaded live; only test data are version-controlled.
- All process inputs/outputs are explicit in `main.nf`, and `publishDir`
  copies the final artefacts to `results/<outdir>/`.

## 8. Threats to validity

1. **Annotation circularity:** mitigated by experimental-only codes, but some
   experimental annotations may still have been assigned with sequence
   knowledge.
2. **Annotation sparsity and imbalance:** *B. subtilis* has ~7% as many
   experimental annotation rows as *E. coli*. Most cross-organism pairs are
   unscorable, and the scorable subset is not representative.
3. **Length/composition confounding:** random pairs are not matched for length
   or amino-acid composition; mean-pooled embeddings can encode both.
4. **Model capacity:** the 8M model is small and mean pooling is lossy;
   results may change with larger models or token-level pooling.
5. **Truncation:** 102 sequences lost residues beyond position 1022.
6. **Metric dependence:** Jaccard is sensitive to annotation depth and
   aspect composition. Resnik and the no-root Jaccard are reported to probe
   this, but no single metric is definitive.
7. **Multiple testing:** only two planned comparisons are made and Holm
   adjustment is applied; this is not an exhaustive specification search.
